## 单元测试覆盖（18 例）

- `stats`：阅读进度取最大页码/总页数、读完恒 100%、无总页数不硬算进度；年度回顾口径（读完按 finishDate、看过按记录或 finishDate、印象深刻含当年有记录的在读作品）；每月分布、时长与收藏计数；首页概览计数。
- `backup`：备份往返校验通过；拒绝非阅迹文件、未知版本、字段缺失作品、指向不存在作品的记录、日期格式错误的记录。
- `db`（fake-indexeddb）：作品/记录新增读回、编辑覆盖不产生副本、删作品连带删记录、删单条记录不影响作品、整库替换（导入恢复底层）。

## 端到端实测流程（2 例，均按要求逐项操作真实界面）

例 1「全流程」：
1. 添加书籍《活着》（作者、分类、总页数 200、在读、开始日期）✅
2. 记一次阅读（读到 80 页、时长 40 分钟、感受、收藏句）→ 详情页进度显示 40% ✅
3. **刷新页面后数据与进度仍在** ✅
4. 再记一次读到 200 页 → 自动变为「读完」、进度 100% ✅
5. 添加电影《重庆森林》（导演、类型、片长）并记观影（感受+台词）✅
6. 编辑电影 → 打开「印象深刻」→ 详情与年度页可见 ✅
7. 年度回顾：读完的书 1、看过的电影 1、印象深刻含该电影 ✅
8. **导出备份**：下载的 JSON 经程序解析校验，app=yueji、作品 2、记录 3 ✅
9. 删除一条观影记录（两段确认）→ 记录消失 ✅
10. 删除整部电影（连带记录）→ 书架只剩《活着》✅

例 2「导出后导入恢复」：
添加《三国演义》→ 导出备份 → 删除该书（书架为空）→ 在「我的」选择备份文件 → 确认恢复 → 提示恢复完成 → 书架里《三国演义》回来 ✅

## 测试中发现并已修复的问题

1. 表单字段容器最初用 `<label>` 包裹，导致分类 chips 等按钮的无障碍名称被污染（首个 chip 的名称吞入了整组文字）。已改为 div 容器，顺带避免点按误触输入框聚焦。
2. e2e 一处时序抖动：保存记录后弹窗关闭瞬间断言同名文本出现两处（表单内+列表内），属测试问题，已改为先等弹窗关闭再断言。
