# 阅迹 · 项目现状报告 v0.5.0（新功能 · 联网找封面 + 资料自动补全）

日期：2026-11-25 · 负责人：Atlas · 触发：所有者使用数日后的明确需求——手动封面要先上网找图、存相册、再回 App 上传，太绕；希望输片名自动上海报，同名靠导演区分，并顺带自动补导演与主演，为以后的查询打底

## 一、需求确认与约束变化

- v0.4.0 任务书曾有「不擅自增加联网搜索封面」的约束——本次是所有者**本人明确提出并授权**联网找封面，该约束就此解除（不是 Atlas 擅自加的）。
- 打磨期「不加新功能」的安排同样由所有者本人在本对话中开口破例，本功能插队完成；其余打磨清单不受影响。

## 二、数据源选型（全部实测后定的，不是拍脑袋）

| 源 | 用途 | 实测结论 |
|---|---|---|
| Bangumi | 电影/剧/动画/音乐封面 + 年份 | CORS 开放、海报图床 CORS 开放；《漫长的季节》《八仙！》都命中 |
| Open Library | 书封 + 作者 + 首版年份 | CORS 开放；《活着》余华两个版本带封面命中 |
| Wikidata | 导演（P57）/ 主演（P161）/ 年份 | 《重庆森林》实测补出：王家卫 + 林青霞、梁朝伟、王菲、金城武 |

落选与原因：iTunes 搜索接口的电影目录实测已下线（连 Avatar 都搜不到）；豆瓣建议接口无跨域许可且海报有防盗链；维基百科在大陆不可达且影片条目常无主图；TMDB 海报与演职员最全，但需要所有者本人注册的免费密钥——留作下一步升级位（密钥只存本机），本版先用免密钥组合把主痛点解决。

## 三、功能实现

- **「联网找封面」**：填好作品名后点按钮，候选海报以三列网格列出（封面 + 名称 + 年份 + 来源），**同名作品全列出来由所有者点选**——正是他设想的「同名靠年份/导演区分」。选中后海报下载到本机、走原有压缩管线（最长边 800 JPEG）存成本地 Blob，断网照常显示，不热链。
- **自动补全（只填空栏，绝不覆盖已写内容）**：
  - 书：作者、首版年份（Open Library）。
  - 电影/剧：年份（Bangumi）；导演、主演（Wikidata，主演取前 6 位）。
  - 完成后表单内明示「已补上：封面、年份、导演、主演」。
- **主演字段**：Work 新增可选 `cast`（Dexie 仍 v1 零迁移；备份仍 v2、往返已测）；电影/剧表单可手填，详情页在作品信息下展示「主演 …」。
- **查询打底**：书架搜索范围扩到主演（占位文案改为「搜索作品、作者或主演」）——他设想的「以后查某部电影/某个演员」先落地一半。
- **失败兜底**：搜不到、网络失败都只给一句提示，手动选图与保存完全不受影响；所有请求都是点了按钮才发，不后台联网。

## 四、验证

- tsc 0 错误；单测 **55/55**（新增 lookup 映射/挑选逻辑 7 例 + 主演备份往返 1 例）；e2e **7/7**（新增：拦截三方接口夹具，走通「搜封面 → 选海报 → 导演/主演/年份自动补上 → 保存 → 详情展示主演」全流程）。
- **真实接口冒烟**（非夹具）：Bangumi《漫长的季节》《八仙》、Open Library《活着》、Wikidata《重庆森林》演职员全链均真实返回正确数据。
- 线上核验：部署后站点与 JS 资源 200，包内版本号 v0.5.0。
