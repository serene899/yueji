# 阅迹 · 项目现状报告 v0.4.3（小修 · 时长记到秒 + 顺带打磨）

日期：2026-11-21 · 负责人：Atlas · 触发：所有者看完电影《八仙》后反馈——记录时长只能填整数，想填「143 分 16 秒」，冒号和小数点都输不进去，数字还被拼成了 14316

## 一、问题诊断

时长的分钟输入框在 onChange 里把所有非数字字符一律剥掉（`replace(/\D/g, '')`），所以「:」和「.」打不进去，前后数字被直接拼接——截图里的 14316 就是这么来的。而且数据模型里时长只有整数分钟，电影天然带秒的片长（143 分 16 秒）无处安放。

## 二、修复：时长支持「分 + 秒」

- **录入**：记录表单与作品表单（片长）统一改成「分钟 / 秒」两个整数框；秒数 ≥ 60 保存时自动进位到分钟。记录表单的时长标签会带上片长提示（如「时长（片长 143 分 16 秒）」）。
- **数据**：Entry 新增可选 `seconds`、Work 新增可选 `durationSec`（Dexie 仍 v1、零迁移；备份仍 v2，新字段随备份往返，校验已放行并有单测锁定；旧数据不受影响）。
- **统计口径**：有效时长 = 分钟 + 秒/60；电影没填时长时片长兜底同样含秒。汇总展示（年度总时长、详情累计）仍按整数分钟呈现（四舍五入）。
- **展示**：单条时长记了秒就精确到秒——详情历史、记录页、首页最近记录、详情页片长都显示「143 分 16 秒」；只记秒显示「45 秒」；没记秒沿用「X 小时 Y 分」旧口径。
- **LIFEOS 交换**：协议未动；阅读分钟按日汇总后四舍五入为整数分钟再发出，无秒数据时输出与旧版逐字节一致。

## 三、顺带打磨（所有者要求整体 UI/逻辑顺带优化）

- 深色模式实拍核查（首页外的主要流程：添加作品、记记录、作品详情）：底栏玻璃、类型色、输入框与标签在深色下均可读，此前「深色未打磨」的遗留项至少在主流程上已确认可用。
- 汇总分钟格式化对小数分钟做取整，避免出现「23.27 分」这类浮点尾巴（秒折算引入小数后的必要修正）。
- 截图素材补齐深色三张（dark-workform / dark-entryform / dark-detail）。
